# Methodology — How We Run This Lit Review

This document is the operational protocol for the agentic-writing wiki. It is **grounded in published evidence**, not invented. Every principle below traces to one of three anchor sources.

This is also the methodology section the eventual paper will report. If we follow this, PRISMA-trAIce compliance comes nearly for free.

## Principles

### 1. Search transparency (PRISMA-trAIce M1, M2, M3)

Every search must be logged in `log.md` with:

- **Tools used**, with versions (M2): e.g., `PubMed MCP server`, `WebSearch via Claude Code`, `Semantic Scholar MCP (semantic-scholar-fastmcp v…)`
- **Full query strings** (M6): not summaries, the actual queries
- **Date range and other filters** (M4)
- **Hit count + how many were retained** (M3)
- **Date the search was run** (PRISMA standard)

> **Why:** PRISMA-trAIce M6 ("report full prompts, parameters, and refinement iterations") is the item authors most often skip and reviewers most often demand. Make it cheap by logging at search time, not at write-up time.

### 2. Two-phase triage (mirrors `/email-scan` and Liu et al.'s Paper Search Specialist → Topic Mining handoff)

- **Phase 1 — Title/abstract sweep.** Decide whether the paper plausibly exemplifies an agentic-writing pattern. Skip field-adjacent papers (general LLM benchmarks, unrelated NLP tasks, etc.).
- **Phase 2 — Full-source ingest.** Read full text or, where unavailable, the abstract + cited methodology section. Write the source page.

Triage decisions are recorded by inclusion (becoming a source page) or omission (remaining only in the search-hit list in `log.md`). Exclusion reasons are documented for any borderline case.

### 3. Pattern-evidence threshold (this wiki's specific rule)

A **concept page** (i.e., a named pattern) requires **≥3 sources** before it leaves `status: provisional`. Below that threshold, the pattern lives as a paragraph in a single source page, not its own concept page.

> **Why:** PRISMA-trAIce D1 (discuss limitations) and the senior-investigator reviewer persona both pressure on single-source claims dressed up as patterns. Three sources is the lowest defensible bar for "pattern, not anecdote."

### 4. Human-as-arbiter (PRISMA-trAIce M8, R1, R2)

**Sean reviews every source-page summary before it is promoted to inform a concept page.** This is non-negotiable.

In paper terms, this is the M8 ("describe human oversight") and R1 ("distinguish AI vs. human decisions in flow diagrams") requirement. Each source page should ideally end with a marker like `> Reviewed by Sean: YYYY-MM-DD` once verified.

Concept-page promotion (provisional → settled) requires explicit human sign-off.

### 5. Multi-tool orchestration, single human-as-Quality-Gate

We are not implementing Liu et al.'s four agents directly. Our architectural mapping:

| Liu agent | Our equivalent |
|-----------|---------------|
| Paper Search Specialist | PubMed MCP, Semantic Scholar MCP, ArXiv via WebSearch |
| Topic Mining & Clustering | Claude + manual organization via wiki structure |
| Academic Survey Writer | Claude writing source/concept pages |
| Quality Evaluator | **Sean** (not an LLM) |

> **Why the Quality Evaluator is human:** Liu et al.'s Quality Evaluator is itself an LLM, which inherits LLM failure modes (citation hallucination, plausible-but-wrong synthesis). Putting Sean in that role aligns with PRISMA-trAIce's human-oversight requirement and is the only way to meet M8/R1/R2 honestly.

### 6. Citation traceability (PRISMA-trAIce M2; quartobot dependency)

Every source page must include a `citation:` frontmatter block with at least one of:
- `doi: 10.xxxx/yyyyy`
- `arxiv: xxxx.xxxxx`
- `pmid: xxxxxxxx`
- `pmc: PMCxxxxxxx`

These are quartobot-resolvable, which means the paper's bibliography will be generated, not hand-curated. Hand-curation is the most common source of citation error in LLM-assisted reviews.

### 7. Prompt + iteration logging (PRISMA-trAIce M6)

For any source-page summary generated by a model:
- The prompt used goes in `log.md` (or a referenced prompt-bank file if it's reused)
- Iterations / refinements are noted
- The model name and version are noted

This is operational tax in the moment but is what makes the paper publishable without M6 deficiencies.

### 8. Failure-mode catalog (the missing safeguard in Liu et al.)

Liu et al. do not directly address citation hallucination. We will. As we encounter LLM failure modes during this review — fabricated citations, misattributed claims, missed key papers, summary drift from source — we add them to a new section at the end of this document and to a concept page `concepts/llm-failure-modes-in-lit-review.md` (once 3+ instances accumulate).

This catalog is itself a contribution the paper can make.

## Operational checklist (per source ingest)

- [ ] Log the search query and date in `log.md`
- [ ] Read source (full text where possible; abstract + methods otherwise)
- [ ] Write `sources/<slug>.md` with citation frontmatter
- [ ] Note the pattern(s) the source exemplifies in the source page
- [ ] If a pattern now has ≥3 sources, promote to a concept page
- [ ] Update `index.md`
- [ ] Append to `log.md`
- [ ] Sean reviews before any concept-page promotion

## Open methodology questions (carry forward)

1. **Token spend** — Liu et al. don't report cost per surveyed topic. We should at least roughly track our cost (search-hit volume × ingest time) as we go.
2. **Whole-field vs. topic-scoped scope** — Liu et al.'s scalability ceiling on "very large" sets suggests we should keep our paper's scope topic-tight rather than field-wide.
3. **Detecting hallucinated citations** — beyond DOI/PMID resolvability, we need a check that the source-page summary's claims actually appear in the source. Cross-check sampling? Reviewer-simulation skill from scriptorium?
